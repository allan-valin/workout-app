## Batch — 2026-07-26 (top-bar space, clock format, Spotify visibility)

- Session clock vanished past 100 minutes. Cause was width, not arithmetic: the labelled
  "Info & notes" TextButton took ~130dp of the action row, leaving the TopAppBar title slot
  ~86dp on a 360dp phone, and `fmt` had no hour rollover so the value only grew. Fixed by
  collapsing the action to an icon and rolling the format over to h:mm:ss at one hour.
  FIXED + verified on the emulator at ~1, ~61 and ~104 minutes — the clock renders in full
  at every step, including the case that used to be invisible.
- The icon-only info button has NO visual long-press tooltip. contentDescription drives
  TalkBack only; a visible tooltip would need a TooltipBox wrapper. Deliberate — the (i)
  glyph carries it. Noted so nobody "restores" a tooltip that never existed.
- New `session_show_estimate` preference (default on) hides the "/ estimated" half of the
  session clock and captions it "elapsed"; the overview bar keeps the pair either way.
  Build + 96 unit tests green. NOT yet exercised on a device — n/v.
- `fmt`'s h:mm:ss rollover also covers the rest/set countdown and stopwatch call sites, whose
  values are NOT bounded (restSecs and secs-mode targetValue are free-text IntFields in the
  editor; the 3600 cap in PlanTransfer.kt:306 only guards JSON import). A 5000s rest now reads
  "1:23:20" instead of "83:20". Beneficial, not a regression.
- Spotify showed nothing at all — no Settings row, no mini-player. Cause: targetSdk 36
  package-visibility filtering hid `com.spotify.music` from PackageManager, so
  `isSpotifyInstalled()` returned false on a phone that had it installed, and both call sites
  took their silent "unavailable" branch. Fixed with a manifest `<queries>` entry.
  VERIFIED ON THE REDMI: the "Controles do Spotify" row appears in Settings and the session
  mini-player renders. This closes the checklist item above — the strip only shows on an
  exercise page, not on the overview list, which is what made a first pass look like a failure.
